# CLAUDE.md: varde-agent-fabric

This repo will be public. Read `README.md` for the architecture and `CONTRIBUTING.md` for the pull request checklist before changing anything. `CONTRIBUTING.md` owns the checklist; the rules below are its safety subset, for agents. Every reachable commit must be safe to publish: a mistake stays in history even after a later commit removes it.

## Rules

- **Nothing private in the repo.** Do not add secrets, private hostnames, tenant paths, deployment values, model weights, real source diffs (a diff taken from a private or customer repo; a synthetic diff in a fixture is fine), or operational logs. These belong in a private overlay (see `CONTRIBUTING.md`).
- **No customer names or data.** Do not name a customer firm, its staff, or its data anywhere: code, comments, docs, tests, fixtures, branch names, commit messages, or issue and PR text. Write "a firm" or "the example firm", never an invented firm name, which can collide with a real one.
- **No internal names in content.** Do not name internal people, agents, hosts, or private repos in code, comments, docs, tests, or fixtures. Use a generic role ("the orchestrator", "a worker", "the reviewer"). Agent names are public, since agents sign commits, but code stays deployment-neutral. The one exception is the agent-path pattern in `scripts/check-public-safety.sh` (`/data/<agent>`) and the case in `tests/test-public-safety.sh` that proves it fires. A tenant here is an agent's account on a host, never a customer. The pattern must name the agents' account names to catch a leaked path; do not remove them. A test that needs an agent or tenant name uses an `example-` name, such as `/data/example-agent`. The `example-` prefix marks the name as fake; a reviewer still checks that a fixture holds no real name.
- **No reviewer credits in comments.** A comment states the constraint or the reason. It does not credit a reviewer, a review round, or a date.
- **If private material lands, stop and tell the operator.** This covers a secret or a customer identifier that reaches a commit, a branch, or a PR, and an internal name that reaches content (the scope of the internal-names rule). The standard attribution in commits and PR footers does not count. Rotate any exposed secret, because deleting it does not make it private again. A follow-up commit that removes the text does not fix it, because history keeps it. Rewriting history is the operator's decision.
- **Run the checks before a PR:** `./tests/test-skeleton.sh`, `./tests/test-public-safety.sh`, and the relevant component tests. `scripts/check-public-safety.sh` catches private keys, AWS access key IDs, agent tenant paths, runtime paths, and Discord webhook URLs. It does not catch names, so the two name rules above depend on review.
- **Keep the public and private sides apart.** A portable change names its public contract and tests. Deployment rollout work stays in the private overlay.
